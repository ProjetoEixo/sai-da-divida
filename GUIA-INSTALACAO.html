Como colocar seu aplicativo no ar

GitHub, Supabase e instalação no celular, sem substituir seus dados antigos.

1. O que você recebeu

Arquivo / pastaPara que serve

O projeto original é ProjetoEixo/sai-da-divida. A reformulação parte do commit 32cb4f30d808aac68081b5f4b0e3d505291a8eed. Trabalhe em uma branch separada antes de substituir a produção.

As telas de login, cadastro, recuperação, contas e reservas, lançamentos, cartões, dívidas, metas, investimentos, patrimônio, calculadoras, holerites e histórico estão incluídas. A autenticação e a sincronização dependem da ativação do banco.

2. Ativar o banco no Supabase

  1. Acesse seu projeto no painel do Supabase.
  2. Abra SQL Editor e crie uma consulta.
  3. Abra o arquivo 001_financeiro.sql, copie todo o conteúdo, cole no editor e execute.
  4. Confira se apareceram as tabelas sdd_documents e sdd_operations no esquema public.
  5. Confira as funções sdd_save_document e sdd_delete_own_account. Elas devem existir no mesmo esquema.

O script adiciona uma estrutura V2 e habilita isolamento por usuário. As tabelas antigas, como entradas, gastos e dividas, permanecem intactas. Os usuários existentes continuam usando o mesmo acesso.

Não desative RLS nem conceda leitura pública aos registros. A chave publicável foi feita para o navegador; a separação dos dados é aplicada pelas permissões do banco e pela identidade de cada usuário. A exclusão de conta é permanente e, por compartilhar o mesmo Supabase Auth, pode alcançar dados da versão anterior vinculados àquele usuário. O aplicativo avisa antes da confirmação.

Referências: SQL Editor e tabelas · RLS e permissões por usuário.

3. Configurar o acesso e os e-mails

  1. Em Authentication, confirme que o acesso por e-mail e senha está habilitado.
  2. Mantenha a confirmação de e-mail conforme sua política. O aplicativo informa quando é necessário confirmar o cadastro.
  3. Em URL Configuration, configure o endereço definitivo do aplicativo.

Para publicação padrão no GitHub Pages, sem domínio próprio, o endereço esperado desta estrutura é:

https://projetoeixo.github.io/sai-da-divida/dist/

Use esse endereço em Site URL e acrescente-o em Redirect URLs. Para testes locais, acrescente:

http://127.0.0.1:4181/

Se publicar em outro domínio ou na prévia privada, use o endereço real correspondente. Preserve endereços antigos enquanto ainda estiver testando a transição.

Em dist/app-config.json, confira:

{
  "url": "https://SEU-PROJETO.supabase.co",
  "key": "SUA-CHAVE-PUBLICAVEL"
}

Use somente chave publishable ou a antiga chave anon. Nunca coloque service_role, senha do banco ou chave sb_secret_ no GitHub ou neste arquivo.

Para trocar a conexão apenas no seu navegador, use Configurações dentro do aplicativo. Para todos os usuários, altere o arquivo de configuração do projeto e publique a alteração.

Referências: URLs de retorno · Acesso por senha e confirmação de e-mail.

4. Atualizar e publicar no GitHub

O projeto agora tem vários arquivos. Substituir somente o HTML antigo não é suficiente.

  1. Abra o repositório e use uma branch separada para revisar a V2.
  2. Inclua index.html, .nojekyll, dist/, supabase/, scripts/, tests/, package.json, pnpm-lock.yaml e a documentação. Não envie node_modules, arquivos de ambiente ou backups financeiros.
  3. Depois dos testes, integre a branch à branch que deseja publicar.
  4. Abra Settings → Pages. Em Build and deployment, escolha Deploy from a branch.
  5. Selecione a branch de publicação e a pasta /(root). Salve.
  6. Aguarde o processamento e use o endereço mostrado pelo próprio GitHub.

A raiz abre o aplicativo em dist/. Não é necessário executar servidor Node no GitHub Pages, instalar pacotes para o usuário final ou adicionar senha do banco ao site.

Enquanto a V2 estiver só em uma branch de trabalho, a versão atual permanece como está. Selecionar a nova branch no Pages ou integrar à branch já publicada pode mudar o site em produção.

Referência: Configurar a publicação no GitHub Pages.

5. Conferir antes de usar com seus dados

  1. Entre na conta e crie uma conta corrente com R$ 1.000,00 de saldo inicial.
  2. Crie uma reserva com saldo zero. Transfira R$ 100,00: devem restar R$ 900,00 disponíveis e R$ 100,00 na reserva, sem receita ou despesa.
  3. Crie uma meta vinculada à reserva: o patrimônio não deve aumentar apenas por criar a meta.
  4. Cadastre um cartão e uma compra de R$ 100,00 em três parcelas. As parcelas devem somar R$ 100,00. Pagar a fatura não deve repetir a despesa.
  5. Cadastre um bem e uma dívida vinculada. Confira se a dívida é subtraída apenas uma vez do patrimônio.
  6. Teste uma calculadora com juros zero. Confira a fórmula, o resultado e o cadastro sugerido antes de salvar qualquer compromisso.
  7. Exporte um backup, recarregue o aplicativo e confira a persistência.
  8. Crie uma segunda conta de acesso e confira que ela não enxerga os dados da primeira.
  9. Teste cadastro, confirmação de e-mail e recuperação de senha com endereços que você controla.

A revisão no navegador real e o teste de isolamento no seu Supabase precisam ser realizados depois da ativação. Os testes locais de conexão não substituem esse teste no seu projeto.

6. Trazer dados antigos e importar holerites

Versão anterior

No modo conectado, abra Configurações → Revisar importação da versão anterior. Revise valores, datas, saldos restantes, taxa e vencimento antes de confirmar. As cópias de receitas e gastos entram como previstas em uma conta nova com saldo zero. Confirme como realizadas apenas as que efetivamente ocorreram, após conferir o saldo inicial. Compras parceladas já encerradas não devem ser perpetuadas.

O processo não reconstrói extratos antigos a partir da data de cadastro. Os registros da versão anterior permanecem nas tabelas antigas. Identificadores de origem evitam importar a mesma cópia novamente.

Holerite em foto ou PDF

  1. Cadastre uma conta corrente ou de dinheiro.
  2. Abra Holerites e selecione um PDF, JPG, PNG ou WebP de até 10 MB. PDFs podem ter até três páginas.
  3. Confira competência, salário-base, proventos, descontos e líquido. Campos ambíguos exigem conferência manual.
  4. Escolha a conta e a data. Marque Já recebi somente se o valor foi recebido; caso contrário, mantenha previsto.
  5. Confirme o lançamento. Somente o líquido confirmado entra como receita.
  6. Nas calculadoras, use Usar base do último holerite conferido e confira médias e adicionais aplicáveis.

O documento é processado no navegador, com componentes carregados sob demanda. Foto, PDF e texto integral não são armazenados. Apenas campos conferidos e identificador do arquivo entram no registro. A leitura pode falhar com fotos inclinadas, baixa resolução ou layouts incomuns; a conferência humana continua necessária.

7. Instalar no celular e usar offline

Android: abra o site HTTPS no navegador e use “Instalar aplicativo” ou “Adicionar à tela inicial”. iPhone: no Safari, use Compartilhar → Adicionar à Tela de Início. A opção também é explicada em Configurações.

O aplicativo pode guardar a interface para abrir offline após o primeiro carregamento. O modo Este dispositivo mantém os registros naquele navegador. O modo conectado requer internet para consultar e salvar dados financeiros. O primeiro uso do leitor de holerites requer internet para os componentes de leitura.

Limpar os dados do navegador pode apagar o modo local. Ele não possui sincronização nem criptografia própria: faça backups e proteja o acesso ao aparelho.

8. Executar e testar no computador

Com Node.js 24 instalado, na pasta do projeto:

node scripts/serve.mjs

Abra http://127.0.0.1:4181/. Não abra o HTML diretamente pelo explorador de arquivos.

Para executar os testes automatizados:

npx pnpm@11.25.0 install --frozen-lockfile
node --test tests/*.test.mjs

As dependências instaladas aqui são de teste. O aplicativo publicado é estático e não exige instalação de pacotes por seus usuários.

Voltar sem apagar dados

Republique a branch anterior ou reverta a alteração de código. Mantenha as tabelas antigas e as tabelas V2; não é necessário apagá-las para voltar. Preserve o backup antes de qualquer substituição de registros.
